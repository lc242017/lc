# 架构设计文档（Architecture Design Document）

> 项目：云购生活新零售——企业级数据仓库与经营分析可视化系统
> 版本：v1.0（第5周整合定稿）　维护人：刘畅　日期：2026-11-23
> 数据来源：第2周数仓架构设计文档 + 第3/4周实现 + 第5周整合
> 定位：描述四层架构、维度建模与技术选型，是全系统的技术蓝图。

---

## 一、总体架构

系统采用"数据链路 → 数仓分层 → 分析应用 → 可视化与部署"的四段式架构：

```
数据源(6份CSV)
    │ 采集
    ▼
ODS 贴源层 ────────────── 原始数据镜像，保留全量
    │ 清洗（五类脏数据）
    ▼
DWD 明细层 ────────────── 维度建模，一单一品粒度事实表
    │ 汇总（天/周/月 × 门店/品类/渠道）
    ▼
DWS 汇总层 ────────────── 轻度汇总，支撑多维分析
    │ 聚合（KPI/排行/占比/分层）
    ▼
ADS 应用层 ────────────── 6 张指标表，直供应用
    │
    ├──► 预测建模（趋势分解 + 线性回归 + 滚动预测）
    ├──► NL2SQL 智能问数（7 类经营问题）
    └──► 可视化（Superset 仪表板 / ECharts 大屏 / Streamlit 问答）
                │
                ▼
        Docker Compose 一键部署
```

## 二、分层职责与命名规范

| 层 | 职责 | 表命名 | 粒度 |
|---|---|---|---|
| ODS | 贴源镜像，原样落地 | `ods_<实体>` | 源系统粒度 |
| DWD | 清洗 + 维度建模 | `dwd_<事实>` / `dim_<维度>` | 一单一品 |
| DWS | 轻度汇总 | `dws_<主题>_<粒度>` | 天/周/月 × 维度 |
| ADS | 应用指标 | `ads_<指标主题>` | 报表粒度 |

## 三、维度建模

### 3.1 方法选择

采用**星型模型**（Kimball 维度建模）：查询路径短、易理解、适合经营分析。

### 3.2 总线矩阵

| 业务过程 \ 维度 | 日期 | 用户 | 商品 | 门店 | 渠道 |
|---|:---:|:---:|:---:|:---:|:---:|
| 订单 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 用户行为 | ✓ | ✓ | ✓ | — | ✓ |

### 3.3 星型模型结构

- **事实表**：`dwd_order`（订单事实，一单一品）、`dwd_order_item`（订单明细，品类分析走此粒度）、`dwd_user_behavior`（行为事实）；
- **维度表**：`dim_user`、`dim_product`、`dim_store`、`dim_date`；
- **关键设计决策（手册差异 D2）**：手册用 `dwd_order.product_id` 关联商品维度，但订单表无此字段；强行加字段会导致行膨胀、GMV 翻倍。故新增 `dwd_order_item` 明细事实表，品类分析走明细粒度。

## 四、存储与性能策略

| 策略 | 实现 | 效果 |
|---|---|---|
| 文件格式 | ORC 列式存储 | 高压缩比、列裁剪友好 |
| 分区 | ADS 表按月分区（`stat_year`） | 分区裁剪，减少扫描 |
| 分区裁剪 | 查询带分区条件 | 压测提速 59% |
| 大 key 加盐 | 两阶段聚合 | 缓解数据倾斜 |
| ADS 预聚合 | 计算前置离线 | 在线查询提速 71% |

### 压测结果（第4周真实数据）

| 场景 | 平均耗时(s) | 提速 |
|---|---:|---:|
| 全表扫描 | 8.572 | 基线 |
| 分区裁剪 | 3.475 | 59% |
| 分区+列裁剪 | 6.081 | 29% |
| ADS 预聚合 | 2.502 | 71% |

## 五、数据质量治理机制

- **五维度检查**：完整性、唯一性、合法性、一致性、准确性；
- **三道防线**：ODS 落地检查 → 清洗环节检查 → DWD 入库检查；
- **修复率口径**：按脏数据行数 vs 字段数区分，避免口径误读（详见清洗报告）。

## 六、技术选型

| 层次 | 技术 | 选型理由 |
|---|---|---|
| 数据采集 | Python / CSV | 教学环境模拟源系统 |
| 数仓 | Hive 4.0（Tez）+ MySQL | 离线批处理 + 元数据/ADS 同步 |
| 本地同构 | SQLite | 无 Hive 集群时的等价替身 |
| 调度编排 | Shell（hr.sh）+ Docker Compose | 串行执行、一键部署 |
| 预测建模 | Python（sklearn / 线性回归） | 趋势分解 + 滚动预测 |
| NL2SQL | LangChain + OpenAI 兼容协议 | 意图识别 + SQL 白名单 |
| BI 可视化 | Superset + ECharts | 交互式仪表板 + 大屏 |
| 问答应用 | Streamlit | 轻量对话式应用 |

## 七、与部署手册的差异及原因

| 编号 | 问题 | 实现处理 |
|---|---|---|
| D1 | 步骤3从步骤6才建的 `dwd_order` 取数 | 改为从 `v_order_clean` 视图生成 |
| D2 | 订单表无 product_id | 新增 `dwd_order_item` 明细事实表 |
| D9 | 无去重环节 | 补 `row_number()` 去重 |
| D3~D10 | percentile 语法、枚举字段、落地语句、修复率口径等 | 逐条见第2周架构文档第八节 |
| W4-1 | Superset 初始化顺序错误 | 改为 `db upgrade → create-admin → init` |
| W4-2 | 容器内 localhost 指向自身 | 用 `172.17.0.1` 网桥网关 |
| W4-3 | 手册要 ADS 表但项目只到 DWD | 第4周补齐 6 张 ADS 表 |
| W4-4 | MySQL 端口写 3306 | 实际映射 3307 |

## 九、已知限制与演进

- Superset 仪表板 UI 图表需手工完成，已提供字段映射说明；
- Hive 官方镜像无 Hive Python 驱动，需定制 Dockerfile；
- 预测采用线性回归，未覆盖季节性等复杂模式，可在依赖就绪后升级；
- 所有数据口径以 `指标定义文档_metrics.md` v1.2 为唯一源头。

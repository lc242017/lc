# 五周端到端串联运行报告

> 执行时间：2026-11-27　｜　环境：Docker Hive 4.0.0 + MySQL 8.0 + Superset 4.1.1 + Streamlit
> 目标：把第1~5周成果串成一条真实可运行的链路，补齐未落到 Hive 的部分，并验证全链路。

---

## 一、运行前诊断：发现的两个断点

五周成果原本分头运行，存在两处未打通的缺口：

| 断点 | 现象 | 根因 |
|---|---|---|
| **断点1：第3周 DWS 层从未上 Hive** | Hive 中只有 `ydsh_ods`/`ydsh_dwd`（第2周）和 `ads`（第4周），没有第3周的 `dws` 库 | 第3周 DWS/ADS SQL 只在本地 SQLite 跑过；Hive 版 SQL 用的是 `status/order_date/product_id`，与真实 Hive 的 `order_status/stat_date + dwd_order_item.product_id` schema 不兼容，从未执行 |
| **断点2：Streamlit 应用数据卷挂载失效** | 应用能启动，但任何问答都报 `FileNotFoundError: /app/../echarts/data/kpi.json` | 上次用 `docker run` 启动时，Windows Git Bash 的 `$(pwd)` 被 Docker 误解析为 `C:\...;C -> \Users\...`，数据卷未挂到代码期望的 `/echarts/data` |

## 二、补齐动作

### 2.1 补齐第3周 DWS 层到 Hive

新增脚本 `sql/week3_dws_on_hive.sql`（本目录），按真实 Hive schema 改写第3周 SQL：
- 有效订单口径：`order_status IN ('已完成','已支付')`（与第4周 ADS 口径一致）
- 品类分析改走 `dwd_order_item` 明细表取 `product_id`
- 渠道取自 `dwd_order.channel`（4 值：APP/PC官网/小程序/门店），非 `dim_store`

新建表（19 条 SQL 全部执行成功）：

| 层 | 表 | 行数 | GMV 合计 |
|---|---|---|---|
| DWS | `dws.dws_order_store_day` | 8,016 | 26,422,854.45 |
| DWS | `dws.dws_category_day` | 2,924 | —（明细口径，见下注） |
| DWS | `dws.dws_channel_day` | 1,463 | 26,422,854.46 |
| DWS | `dws.dws_order_week` | 53 | 26,422,854.46 |
| DWS | `dws.dws_order_day` | 366 | 26,422,854.46 |
| ADS | `ads.ads_channel_share` | 4 | 四渠道占比 24.8%~25.2% |
| ADS | `ads.ads_category_top10` | 10 | Top1 运动户外 6,503万（明细口径） |
| ADS | `ads.ads_kpi_overall_w3` | 1 | 26,422,854.45 / 9,992 单 |
| ADS | `ads.ads_kpi_month_w3` | 12 | 12 个月 |

> 注1：DWS 订单口径 GMV 2,642万（9,992 单）与第4周 `ads_kpi` 全量口径 3,970万（15,000 单）**不同**，差异来自有效状态过滤。两套口径并存、各自自洽，已在联调清单中标注，严禁混用。
> 注2：品类相关表（`dws_category_day`/`ads_category_top10`）走 `dwd_order_item.item_amount` 明细金额，全表合计 6.45 亿，与订单实付 GMV 差异大——该字段是行级金额口径（含优惠前/分摊差异），**仅用于品类结构分析，不作为 GMV 对外口径**。品类 GMV 对外统一以第4周已验证的 `ads.ads_category_sales`（net_sales）为准。

### 2.2 修复 Streamlit 数据卷

删除旧容器，用 Windows 绝对路径重新挂载数据目录到代码期望的 `/echarts/data`。修复后 6 个 JSON 数据文件正确挂载，NL2SQL 问答恢复正常。

## 三、五周串联链路（实测通）

```
第1周 ODS  ydsh_ods.ods_order            15,600 行
   ↓ 清洗去重（第2周）

   ↓ 汇总（本次补齐）

```

## 六、遗留说明

1. ECharts 大屏服务（8090）由宿主机 Python 进程托管，会话结束后如需继续使用需重启 `python echarts/serve.py`。
2. Streamlit 数据卷挂载已修复，但容器由 `docker run` 创建（未纳入 compose 编排），重启 Docker 后 `restart: unless-stopped` 会自动恢复。
3. 两套 GMV 口径（全量 3,970万 / 有效订单 2,642万）并存，对外汇报统一用全量口径，DWS 层分析用有效订单口径，严禁混用。
4. 复购率在"已完成+已支付"口径下为 100%（模拟数据中 1000 用户均有 2+ 单），属数据特性而非计算错误；单"已完成"口径为 98.1%。

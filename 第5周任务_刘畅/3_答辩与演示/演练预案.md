# 答辩演练预案

> 项目：云购生活新零售——企业级数据仓库与经营分析可视化系统
> 用途：手册步骤4"演练一次完整演示，控制时间，预演启动失败等突发情况"
> 演练重点：时间控制 + 突发情况兜底

---

## 一、演练检查清单（答辩前一天完成）

- [ ] 按 `10分钟演示脚本.md` 完整演练 1 次，计时 ±30 秒内
- [ ] 所有页面/文件提前打开，避免现场加载等待
- [ ] 大屏 `index_standalone.html` 双击验证可离线打开
- [ ] NL2SQL 三个演示问题预跑一遍，确认返回正确
- [ ] Superset 仪表板截图存档（作为兜底素材）
- [ ] 预测图表 `forecast_vs_actual.png` 确认可打开
- [ ] Git 仓库确认已 push，演示链接可用
- [ ] `.env` 确认未入库，答辩材料无真实密钥

## 二、时间控制表

| 段 | 计划 | 超时保护 |
|---|---|---|
| 业务价值开场 | 1 min | 超过 1.5 min 直接进入架构 |
| 数据链路与数仓 | 2.5 min | 只讲 3 个硬门槛，细节留给问答 |
| 预测建模 | 1.5 min | 只展示结果图，不展开公式 |
| NL2SQL 问数 | 2 min | 演示 3 个问题即可 |
| 可视化大屏 | 2 min | 大屏为主，Superset 用截图带过 |
| 一键部署 | 1 min | 一条命令 + 一句话收尾 |

> 总时长 10 min，预留约 1 min 缓冲；若某段超时，从"可视化大屏"段扣减。

## 三、突发情况预案

| 突发情况 | 应对方案 |
|---|---|
| **大屏打不开 / 网络不通** | 用提前存档的截图（Superset 仪表板 + ECharts 大屏）展示，口头说明逻辑 |
| **NL2SQL 现场返回异常** | 切到预跑结果的截图/JSON，说明"已验证 7 类问题全部正确" |
| **Docker 服务未启动** | 不现场启动（耗时），用 `docker ps` 截图 + `docker compose up -d` 命令说明，强调可复现 |
| **Hive 查询慢/超时** | 用 ADS 预计算数据演示，说明生产环境走离线预聚合 |
| **忘词/卡壳** | 回到"三个硬门槛数字"（15000 / 11-12 归零 / 39,708,649.13），数字是最稳的锚点 |
| **评委追问超出准备** | 诚实说明边界："这是教学环境规模下的实现，生产环境需要……"，不编造 |

## 四、演示话术原则（手册答辩策略）

1. **先讲业务价值，再讲技术亮点**——评委先听懂"解决了什么问题"；
2. **每个数字指向可追溯来源**——核对清单、指标文档、执行日志；
3. **突出三个记忆点**：口径统一、端到端闭环、一键部署；
4. **遇到质疑不硬辩**——用"口径文档是这样定义的"作为共同依据。

## 五、问答环节策略

- 高频问题已从四个维度准备（见 `5分钟问答库.md`）：建模依据 / 指标口径 / AI 边界 / 部署原理；
- 答题结构：**30 秒结论 + 展开理由**，不啰嗦；
- 遇到不会的问题：承认边界 + 给出改进方向，体现工程判断力。
